# Classifying hand-authored vs generated vs vendored

Raw `additions` is wrong by 2x-30x in most repos. This is the single largest
source of error in GitHub-derived performance evidence, and it always inflates
rather than deflates, which makes it flattering and therefore dangerous.

## How to verify a rule (do this, don't guess)

Never add a pattern because it looks generated. Confirm it:

```bash
# 1. Codegen marker in the file header
gh api repos/OWNER/REPO/contents/path/to/file.go --jq .content \
  | base64 -d | grep -m2 -i "code generated\|DO NOT EDIT\|autogenerated"

# 2. A generator script that produces it
gh api repos/OWNER/REPO/contents/path/to/generate.sh --jq .content | base64 -d

# 3. Documented vendoring
gh api repos/OWNER/REPO/contents/path/README.md --jq .content | base64 -d | head -20

# 4. The diff itself (fastest for a specific PR)
gh api repos/OWNER/REPO/pulls/N/files --paginate \
  --jq '.[]|[.additions,.filename]|@tsv' | sort -rn | head -15
```

Write the evidence into the rule's `verified` field. It ships in the output.

## Verified in practice

Each of these was confirmed by the method in the right column, and each was
found *because* the audit flagged an implausible number.

| Pattern | Bucket | Why | Confirmed by |
|---|---|---|---|
| `zz_generated`, `_generated.go` | generated | deepcopy-gen / codegen | Go convention + header marker |
| `pkg/resource/*/` except `hooks.go` | generated | AWS ACK controller scaffolding | all 10 files carry `Code generated by ack-generate. DO NOT EDIT.`; `hooks.go` has none |
| `/crds/`, `config/crd/`, `helm/crds/` | generated | controller-gen output | CRD YAML is never hand-written |
| `versioned_docs/`, `versioned_sidebars/` | generated | docusaurus release snapshot | a "cut docs" PR copies the whole doc tree |
| `grafana/*.json` | generated | Grafana UI export | 16,470 lines across 2 dashboards in one PR |
| `aws-models/*.json`, `testdata/models/apis/**` | vendored | AWS SDK Smithy models | file opens `{"smithy": "2.0"...}` |
| `embeddedschemas/swagger_*.json` | vendored | k8s OpenAPI specs | `generate.sh` curls them from kubernetes/kubernetes tags |
| `charts/`, `flux/**/crds/` | vendored | vendored Helm charts | repo's `charts/README.md`: "Vendored Helm Charts" |
| `ATTRIBUTION.md`, `LICENSE*`, `NOTICE` | vendored | generated license manifest | largest "hand" file in every ACK bootstrap PR (1.7k-2.6k lines) |
| `vendor/`, `go.sum`, `*.lock` | vendored | dependency trees | universal |

## The trap that cost two wrong numbers

**Do not blanket-exclude `docs/`, `website/`, or `site/`.**

Tempting, because release doc snapshots are huge. But hand-written technical
documentation lives there too. In one scan a blanket `^website/` rule discarded
1,342 lines of hand-authored `generator.yaml` reference documentation as
"generated" — real authored work, erased.

Target the generated subtree specifically:

- exclude: `versioned_docs/`, `versioned_sidebars/`, `.docusaurus/`
- keep: `website/docs/**/*.md` written by a person

Check the diff before deciding. Prose reads like prose.

## Ecosystem cheatsheet

**Go / Kubernetes** — `zz_generated*`, `*.pb.go`, `config/crd/`, `vendor/`,
`go.sum`, `mocks/`, `client-go` generated clientsets, `api/openapi-spec/`.

**AWS ACK** — high generated ratio by design: a small `generator.yaml` edit
produces thousands of lines. `pkg/resource/*/` is all generated except
`hooks.go`; `apis/v1alpha1/*.go` is generated. `generator.yaml` and
`pkg/resource/*/hooks.go` are the real authored surface. A "bootstrap
controller" PR is ~75 files and almost entirely codegen.

**JS/TS** — `package-lock.json`, `yarn.lock`, `dist/`, `build/`,
`__snapshots__/`, `*.d.ts` when emitted.

**Rust** — `Cargo.lock`, `target/`, `bindings.rs` from bindgen.

**Python** — `*_pb2.py`, `poetry.lock`, `migrations/` (framework-generated),
`.egg-info/`.

**Protobuf/gRPC** — everything under a `gen/` or `proto/gen/` prefix.

## Beyond path patterns

Path regex is a heuristic. It misses:

- **Reformat churn** — additions ≈ deletions means a formatter ran. `audit.py`
  flags this; a 15,660/15,115 PR is not 15k new lines.
- **Copied subtrees** — the same tree committed under two prefixes counts
  twice. Detected via repeated (basename, line-count) pairs inside one PR; one
  real case was 16,163 duplicated lines, 11% of that person's total.
- **Fork duplicates** — a PR to a personal fork and its upstream twin are the
  same work. `build.py` separates `hand_additions_in_forks`.
- **Vendored code with no marker** — some copied files look hand-written.
  Check `git log --diff-filter=A` for a bulk-add commit.

When a heuristic can't settle it, keep the lines in `hand` and add a caveat.
Overstating with a warning beats silently deleting someone's work.
